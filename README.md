# ttrpg-city-builder

Песочница роста поселения для настольных ролевых игр. Показывает прогрессию
численности во времени, позволяет встать в любой год и посмотреть срез:
население, фаза, темп роста, доступные строения и что упирается в потолок.

Сеттинг — усреднённое тёмное фэнтези: магия есть, но доступна не каждому, а
технологии развиваются с оглядкой на магию (в сильно магических регионах часть
технических зданий не разблокируется, и наоборот).

## Модель

Вход разбит на **домены конфигурации**, которые через стабильный промежуточный
слой **рычагов (Levers)** кормят **погодовую эволюцию состояния**:

```
ДОМЕНЫ ──contribute()──▶ LEVERS ──▶ ПОГОДОВАЯ ЭВОЛЮЦИЯ ──▶ ИТОГ
(география, геология,    (потолок K,   (население, состав,    (статус,
 климат, основатели,      миграция,     секторы, статус,        крах/успех,
 живность, соседи,        смертность,   назначение)             цель)
 политика, цель,          раздачи…)
 поддержка, магия)
```

Ядро — рождаемость/смертность с насыщением у потолка `K` + **миграция,
пропорциональная живому сообществу** (люди едут туда, где уже есть люди и
работа, а не в «пустую ёмкость»). Поселение имеет память — два медленных стока:

- **Развитость** (инфраструктура): строится поддержкой, навыками и достатком,
  разрушается набегами и пожарами, поднимает потолок и притягательность.
- **Достаток** (выпуск на душу): следует за структурой экономики (торговля и
  ремёсла богаче натурального земледелия), минус налоги; питает миграцию и
  статус.

Статус считается по **сглаженному 5-летнему темпу** и абсолютному размеру
(деревня в 40 душ после чумы — «борьба», а не «процветание»), а назначение
имеет **размерные ворота с гистерезисом**: торговым городом нельзя быть
вчетвером, усохший город честно понижается.

Кроме того:

- **K** собирается из вкладов всех доменов (еда, вода, импорт по тракту/реке,
  безопасность, санитария, магия).
- **Время**: климат сдвигается, строится тракт, начинается война, меняется
  сюзерен — через расписание; **поддержка — трактория** (инвестиции → субсидии →
  соцпомощь) с keyframes; ресурс **истощается** (шахтёрский посёлок может
  откатиться к аграрному).
- **Не любое поселение выживает** — крах по причинам (голод, обезлюдение,
  конец поддержки до самоокупаемости).
- **Цель основания** задаёт критерии успеха; **назначение** поселения
  эмерджентно из доминирующего сектора и позиции, меняется во времени.
- **Диаграммы**: экономика по секторам и состав населения (местные / приезжие /
  проезжие) донат-чартами на срез любого года.

Числа намеренно «играбельные»: это прикидка динамики для стола, не симулятор
реальности.

## Архитектура

Слоистая, данные отделены от представления. Ключ — развязка «что задаёт игрок» и
«что потребляет модель» через слой рычагов: добавить новый домен = добавить
контрибьютор, симуляция не меняется.

```
src/
├── domain/      чистый TS: модель. Без React, без строк — только id.
│   ├── types.ts        контракты (WorldConfig, Levers, YearState, Outcome…)
│   ├── config/*.ts     по домену: тип + пресеты + contribute(); index.ts — реестр
│   ├── levers.ts       buildLevers() → capacityFrom() / normalizeSectors()
│   ├── trajectory.ts   интерполяция поддержки + применение расписания
│   ├── simulate.ts     (WorldConfig) => SimResult — pure погодовой автомат
│   ├── outcome.ts      статус/крах · designation.ts — эмерджентное назначение
│   └── buildings.ts · phases.ts · rng.ts
├── i18n/        id → строки (ru/en), Intl-форматирование. en задаёт форму
│   └── locales/{en,ru}.ts  типа Messages, ru обязан совпадать (проверка при сборке)
├── state/       config.ts (reducer + пресеты + deep-set по пути) ·
│                persistence.ts (localStorage + экспорт/импорт JSON) · useSimulation
├── components/  ConfigPanel (сворачиваемые домены) · Donut/Donuts · OutcomePanel ·
│                NeighborsEditor · ResourceEditor · SupportEditor · ScheduleEditor …
└── lib/         inputs.tsx (примитивы) · path.ts (deep-set) · ui.ts (палитры)
```

Доменный слой ничего не знает про React и язык: домены, здания, секторы, статусы
и назначения несут стабильные `id`, а строки живут только в `i18n`. Поэтому
модель тестируется в изоляции, добавить язык — один файл в `locales/`, а добавить
домен — один модуль в `domain/config/` + строки.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build
npm run preview  # предпросмотр production-сборки
```

## prototype/

`prototype/settlement-calc.html` — исходный одностраничный прототип (один HTML-файл,
открывается двойным кликом, без сборки). React-версия — его развитие.
